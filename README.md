# StellaSora 本地服 · 活动任务进度同步（ActivityTaskSync）

> 症状：**活动关卡打通了，活动任务却一直停在 0/xxx**；灾变防线（Cataclysm Survivor）打完也看不到赛季/排行记录。
>
> 原因：本地服务端（[Nebula](https://github.com/Melledy/Nebula)）目前**只建了任务条目、从不写进度**，也没有 `ActivityTaskRewardReceive` 处理器（连"领取"都没有服务端逻辑）；灾变防线的排行处理器同样没实现。
>
> 所以这个工具**不是一键全通**，而是：**按你真实的通关记录，把该涨的进度涨上去**。打一关、结算一次，进度就往前走一点，剩下的还是要自己打。

## 它怎么算进度（逐条规则）

| 任务条件（`CompleteCond`） | 含义 | 本工具的计算 |
|---|---|---|
| `149` | 单局拿到 N 分 | 进度 = **通关记录引用到的 build 里最高的分数**（上限 = 任务目标）。打得越高，进度越涨 |
| `150` | 通关指定关卡 | 该关有通关记录 → 1/1 |
| `110` | 指定关卡拿 3 星 | 该关星级 = 3 → 1/1 |
| 其它（如"等主线更新"的占位任务） | — | 不动 |

关卡名来自任务描述文本，工具会把描述里的关卡名对到实际关卡；同名关卡（普通/困难）优先取**已通关**的那个。

## 用法

```bat
:: 结算一次（推荐在关掉游戏、服务端已退出后跑）
run.cmd "D:\Stella Sora" 10003

:: 只看会改什么，不写库
run.cmd "D:\Stella Sora" 10003 dry

:: 守着：你关游戏、服务端退出后自动结算一次（可以挂在后台一直开着）
run.cmd "D:\Stella Sora" 10003 watch
```

- 第一个参数：本地服包根目录（里面有 `Server\`）
- 第二个参数：玩家 UID（服务端日志登录成功那几行里有，或 GM 工具里显示的）
- 第三个参数：`dry` 只检查 / `watch` 自动等服务器退出后结算

## ⚠️ 为什么要"关掉游戏再跑"

服务端会把在线玩家的数据**缓存在内存里**，并在保存时覆盖数据库。所以：

- **服务端还开着时改库会被覆盖** → 工具检测到 `java.exe` 在跑时会照样写，但你的改动可能失效；
- 正确姿势：关游戏（让服务端把数据落盘并退出）→ 跑工具 → 再启动游戏；
- 想省事就用 `watch` 模式，它会一直等，直到服务端退出才动手。

## 奖励怎么办

服务端没有"活动任务领奖"处理器，所以任务达标后**按钮点不动**。工具有两个办法：

1. 结算完会打印一条现成的 GM 邮件命令，例如：
   `mail "活动任务奖励" "活动任务达标，奖励自动补发。" 73117:15000 82001:240 82004:280 @10003`
   你进游戏后把它丢给 GM 工具（或直接 `POST /api/command`）就发到邮箱了；
2. 或者加 `--send-mail` 让工具自己发（**必须玩家在线**，否则返回 `Targeted player not found or offline`）。

## 需要什么

- 本地服自带的 Java 21（`Server\Runtime\Java\bin\java.exe`，`run.cmd` 会自动用）
- 服务端的 `Server\lib\Nebula.jar`（工具拿里面的 MongoDB 驱动当依赖）
- MongoDB 在跑（正常启动器启动的服务端就会带上；工具本身不启动服务端）

## 回滚

工具只改 `activity` 集合里**你这条玩家**记录的 `TaskActivity` 任务 `curProgress`，不改别的：

- 跑之前先复制一份 `存档\Database`，要还原就整份覆盖回去；
- 或者删掉 `run.cmd` 同目录生成的 `pending_rewards.log`（如有）并把任务进度归零。

## 局限（写清楚免得误会）

- 这是**补进度显示 + 补奖励**，不是把功能实现了：领奖按钮依旧点不动、服务端也不会自己记账；
- `149` 类分数任务用的是"通关记录里最高的 build 分数"，模拟器没单独存"单局分数"，这是最接近的可得数据；
- 灾变防线的**赛季排行**仍需要上游实现（本工具不碰）；
- 上游一旦实现活动任务逻辑，请停止使用本工具。
